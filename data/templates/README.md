# 施設データ 入力手順

このフォルダには、施設データをご入力いただくための入力シートが入っています。

| ファイル | 内容 |
|---|---|
| `01_facilities.csv` | **施設シート** — 建物ごとに1行 |
| `02_entry_points.csv` | **車寄せ・エントランスシート** — 進入口ごとに1行 |

いずれも Excel でそのまま開けます。サンプルとして3〜4行を記入済みですので、
**サンプル行を上書きするか、削除して**ご入力ください。

---

## 全体の流れ

1. `01_facilities.csv` に施設を1行ずつ入力する
2. `02_entry_points.csv` に、その施設の進入口を入力する（1施設に複数行になります）
3. 写真・案内図を命名規則に沿ってリネームし、共有フォルダへ入れる
4. 当方へご連絡いただく

**全部を一度に揃える必要はありません。** できたところまでで結構です。
まずはホテル・レジデンスから、揃った施設から順にお送りください。

| 郵便番号 | | |
| 都道府県 | ● | |
| 市区町村 | | |

## 2. 車寄せ・エントランスシート (`02_entry_points.csv`)

**このシートがアプリの中核データです。** 同じ建物でも進入口ごとに経路も
注意点も異なるため、進入口の数だけ行を作ってください。

| 列 | 必須 | 入力内容 |
|---|---|---|
| 施設名 | ● | 施設シートに書いた施設名と**完全に同じ表記**にしてください |
| 進入口記号 | ● | `A` `B` `C`… 施設内で重複しないアルファベット1文字。写真のファイル名と対応します |
| 区分 | ● | 車寄せ / エントランス / 駐車場入口 / バス乗降場 / 関係者用 |
| 名称 | ● | 「正面車寄せ（メインポーチ）」など、現場で通じる呼び方 |
| 進入方法の説明 | ● | どの道から入り、どう進むか。**ドライバーに話しかけるつもりで**書いてください |
| 進入元の道路・方向 | | 「海岸通り（北行き）から」など |
| ナビ緯度 / ナビ経度 | ● | → 下記「座標の取り方」 |
| 停車位置緯度 / 停車位置経度 | | 進入地点と停車位置が離れている場合のみ |
| 高さ制限cm | | ハイヤー・ワゴンが入れるかの判断に使います |
| 屋根 | | `あり` / `なし` |
| 24時間 | | `可` / `不可` |
| 注意事項1・2 | | 下記参照。3件以上ある場合は備考欄へ |
| 注意1_開始時刻 / 終了時刻 | | `17:00` の形式。**時間帯が決まっている注意事項のみ** |
| 注意1_曜日 | | `1,2,3,4,5`（月〜金）。全曜日なら空欄 |
| 備考 | | |

### 注意事項の時間帯を分けて入力していただく理由

「17〜20時は送迎バスが停車するため通過できません」という情報を、時間帯と本文に
分けて登録すると、アプリが**その時間帯にだけ赤く強調表示**できるようになります。

運転中に読む情報は少ないほど安全なため、「今は関係ない注意事項」を目立たせない
ようにしています。時間帯が決まっていない注意事項は、時刻欄を空欄にしてください。

## 3. 座標の取り方

**建物の中心ではなく、実際に車を停める位置**の座標が必要です。
一般的な地図アプリは建物の代表地点を案内するため、車寄せまで数十メートル
ずれることがあり、そのずれがこのアプリで解決したい問題そのものだからです。

### 手順

1. パソコンで Google マップを開く
2. 目的の地点（車寄せの入口）を**右クリック**
3. メニューの一番上に数値が表示されます（例：`35.6656, 139.7604`）
4. その数値をクリックするとコピーされます
5. 「ナビ緯度」に前半（`35.6656`）、「ナビ経度」に後半（`139.7604`）を貼り付け

### どこの座標を取ればよいか

**車寄せに入るために曲がる地点**（進入レーンの入口）をお勧めします。
建物の敷地内ではなく、**道路上の「ここで曲がる」地点**です。

### 難しい場合

**空欄のままで結構です。** 住所と進入方法の説明から当方が仮設定し、
管理画面の地図上でピンをドラッグしてご確認いただく形にできます。
後からの微調整も簡単に行えますので、無理にご入力いただく必要はありません。

## 4. 写真・案内図のファイル名

```
{施設コード}_{進入口記号}_{種類}_{連番}.jpg
```

施設コードは当方で採番してお返ししますので、**それを受け取ってからリネーム**
していただく形が確実です。先に撮影を進められる場合は、
`施設名_A_車寄せ_01.jpg` のように**日本語のままで結構です。**当方でリネームします。

### 種類

| 種類 | ファイル名に使う語 | 内容 |
|---|---|---|
| 進入路 | `approach` | 進入してくる道路から見た様子 |
| 車寄せ | `dropoff` | 停車位置そのもの |
| エントランス | `entrance` | 建物の入口 |
| 夜間 | `night` | 夜間の見え方（照明・視認性が昼と大きく異なるため） |
| 進入案内図 | `diagram` | 進入経路の図。1進入口につき1枚 |
| 外観 | `exterior` | 施設全体の外観 |

### 例

```
HTL-0001_A_dropoff_01.jpg      グランドホテル汐留 / 正面車寄せ / 車寄せ写真
HTL-0001_A_night_01.jpg        同 / 夜間写真
HTL-0001_A_diagram_01.png      同 / 進入案内図
HTL-0001_B_approach_01.jpg     同 / 宴会場エントランス / 進入路写真
RSD-0003_exterior_01.jpg       レジデンス / 施設外観（進入口記号は不要）
```

### 推奨仕様

| 項目 | 推奨 |
|---|---|
| 写真 | 長辺 1600px 以上。スマートフォンの標準設定で撮影すれば十分です |
| 案内図 | PNG 形式（線と文字が潰れないため）。PDF でも当方で変換します |
| 枚数 | 1進入口あたり 3〜5枚 |

## 5. よくあるご質問

**Q. 全部揃わないと開発が始められませんか？**
いいえ。仮の画像とサンプル文言で全画面を先に作り込みますので、開発は止まりません。
実データは管理画面から差し替えるだけで反映され、画面の作り直しは発生しません。

**Q. 写真がまだ撮れていません。**
文章と座標だけでも公開できる設計にしています。写真は後から追加できます。
むしろ、**完成した画面を見てから「どんな写真を撮るべきか」を判断していただく**方が、
撮り直しが減ります。

**Q. 1つの施設に進入口がいくつもあります。**
何行でも作っていただいて構いません。レジデンスやホテルでは
「来客用」「居住者用」「宴会場」「荷捌き」と4〜5箇所になることも想定しています。

**Q. Excel で開くと文字化けします。**
UTF-8 形式で保存しています。文字化けする場合はお知らせください。
Excel 形式（.xlsx）でお送りし直します。

**Q. 途中まで入力した状態で送っても大丈夫ですか？**
問題ありません。むしろ早い段階で一度いただけると、形式の認識違いを
早く発見できます。1〜2施設分の入力が終わった時点で一度お送りいただけると確実です。
