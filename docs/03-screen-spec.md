# 画面一覧・画面遷移

作成日: 2026-08-07 / 対象: 初期版 (MVP)
ルーティング: expo-router（ファイルベース）

---

## 設計の前提

このアプリは**運転前後の停車中に、短時間で操作される**。したがって:

1. **検索からナビ開始までの操作を最小化する** — 目標は「起動 → 検索 → 施設 → ナビ」の4アクション
2. **タップ目標を大きく取る** — 手袋着用や車内の揺れを想定し、最小 48dp
3. **通信が無くても全機能が動く** — 地下・高架下・トンネル内で使われる
4. **ダークテーマ固定** — 夜間走行中の視認性を優先し、明暗の切り替えによる眩惑を避ける

## S-01 検索・施設一覧

デモ画面1に対応。

| 要素 | 仕様 |
|---|---|
| ヘッダー | 「ドライバー専用 / 車寄せナビ」＋1行の説明 |
| 検索窓 | 施設名・かな・別名・住所を対象。**入力の都度、端末内で絞り込む**（通信なし） |
| カテゴリチップ | すべて / ホテル / レジデンス / 商業施設 / オフィスビル / 病院 / 駅・空港。横スクロール |
| 検索結果 | 件数表示 ＋ カード一覧 |
| カードの内容 | サムネイル写真、施設名、住所、**進入口の件数バッジ**、`>` |
| 管理画面リンク | 初期版ではデモ用。本番では非表示または要ログイン |

**検索の仕様** — 表記ゆれを吸収する。

- ひらがな / カタカナ / 半角カナ を同一視する
- 全角英数 / 半角英数 を同一視する
- 別名 (`aliases`) も検索対象に含める
- 部分一致（前方一致に限定しない。「汐留」で「グランドホテル汐留」が出る）

**空状態** — 検索結果0件のとき、「別名でお試しください」「カテゴリ絞り込みを解除」への導線を出す。

## S-02 施設詳細

デモ画面2に対応。**このアプリで最も重要な画面。**

| 要素 | 仕様 |
|---|---|
| ヒーロー画像 | 施設外観。無い場合は最初の車寄せ写真で代替 |
| 戻るボタン | 左上。画像に重ねて配置 |
| カテゴリバッジ | |
| 施設名・住所 | |
| 施設概要 | 2〜3行 |
| **進入口セレクタ** | 進入口が複数ある場合にタブ表示。区分（車寄せ/エントランス）＋名称の2段 |
| 進入方法の説明 | 選択中の進入口の `approach_text` |
| **注意事項** | 下記参照 |
| 進入案内図 | タップで全画面 (S-04) |
| 現地写真 | 横スクロール。タップで全画面 (S-03) |
| 諸元 | 区分、緯度経度、高さ制限、屋根、24時間可否 |
| **ナビ開始ボタン** | 画面下部に固定表示。スクロールしても常に見える |

### 注意事項の表示ルール

`cautions` の時間帯情報を使い、**今この瞬間に該当するものを優先表示**する。

| 状態 | 表示 |
|---|---|
| 現在時刻が適用時間帯内 | 強調表示（オレンジ枠 ＋ 警告アイコン）。「**現在該当**」ラベル付き |
| 適用時間帯外 | 通常表示。「17:00〜20:00」と時間帯を明記 |
| 常時適用 | 通常表示 |
| `severity = critical` | 常に強調表示 |

運転中に読む情報量を減らすことが安全に直結するため、
「今は関係ない注意」を目立たせない設計とする。

### ナビ開始の動作

`nav_lat` / `nav_lng`（進入レーン上の地点）を目的地として、Google マップアプリを起動する。

| プラットフォーム | 遷移先 |
|---|---|
| Android | `google.navigation:q={lat},{lng}&mode=d` |
| iOS | `comgooglemaps://?daddr={lat},{lng}&directionsmode=driving` |
| 起動できない場合 | `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}&travelmode=driving` |

> Android 11 以降では `canOpenURL()` にマニフェスト宣言が必要になるため、
> **判定を行わず `openURL()` を直接呼び、失敗をキャッチしてブラウザ版へ
> フォールバックする**方式を採る。判定に依存しないぶん堅牢になる。

### 補助アクション

「座標をコピー」「住所をコピー」を用意する。
**多くのドライバーは配車システム備え付けのナビを使っており**、Google マップに
遷移せず座標だけ欲しいケースがあるため。実装コストは小さく、実用価値が高い。

## S-06 初回データ同期

初回起動時のみ。施設データと写真の初回取得を行う。

- 進捗バーと件数を表示する
- 失敗時はリトライ導線を出す
- **写真は遅延取得**とし、テキストデータの取得完了時点で S-01 へ進める
  （初回起動の待ち時間を短くするため）

### A-05 が管理画面の中心

デモ画面4の「編集」に相当。ここの使い勝手が、150件・3,000件への拡張可否を決める。

| 機能 | 仕様 |
|---|---|
| **地図ピン指定** | Google マップ上でピンをドラッグして `nav_lat/lng` を設定。住所からの初期表示に対応 |
| 停車位置ピン | ナビ地点とは別に2つ目のピンを配置 |
| 写真アップロード | ドラッグ＆ドロップ、複数同時、並べ替え、キャプション編集 |
| 仮画像フラグ | アップロード時に自動判定（プレースホルダー画像との一致）＋手動切替 |
| 注意事項 | 行の追加・削除、時間帯と曜日をUIで指定 |
| プレビュー | **アプリと同じ見た目**で確認できるプレビューパネル |

### A-02 ダッシュボードに「仮画像が残っている施設数」を出す理由

実データの入稿が段階的に進むため、**何がまだ揃っていないかが一目で分かる**
必要がある。この数字が0になることが、初期データ整備の完了条件になる。

## 実装順序

管理画面を先に作ることで、アプリの実装と並行してデータ登録を進められる。

| 順序 | 対象 | 理由 |
|---|---|---|
| 1 | A-01, A-03, A-04, A-05, A-06 | データ登録を最速で開始可能にする |
| 2 | A-07 一括インポート | CSV での初期投入 |
| 3 | S-06, S-01, S-02 | アプリの主要導線 |
| 4 | S-03, S-04, S-05 | 補助画面 |
| 5 | A-02, A-08, A-09 | 運用機能 |
