## 12. PWA 化（配信基盤を含む） — 依頼 / 4.0人日

「ストアの利用料が不要になる」「より多くの人が使える」という理由で、

**なぜ範囲外か:** 合意書は App Store / Google Play での配布を前提と
しており、web での提供は含まれていない。

内訳:

| 作業 | 人日 |
|---|---|
| Expo SDK 54 → 57 への更新（RN 0.81 → 0.86） | 1.0 |
| PWA の基盤（manifest・Service Worker・アイコン・オフライン設計） | 1.0 |
| 保存先を SQLite から IndexedDB へ移行 | 1.5 |

必要とし、**Safari では動かない**。iPhone で使えないなら、PWA にする
理由（より多くの人が使える）が成り立たない。

**ネイティブ向けの作業が無駄になった点:** react-native-maps の導入と
APK のビルドは PWA では使わない。方針決定前に着手していたため。

## 13. 施設数 150件 → 193件 — 依頼 / 1.0人日

`docs/04-scope-and-acceptance.md` の受入条件は「**150件を登録できる状態**」。
2026-09-03 にいただいた一覧は **193件**で、43件多い。

**投入そのものは自動化してあるため、件数に比例した手間はかからない。**
加算しているのは、件数が増えたことで新たに必要になった次の作業。

| 作業 | 人日 |
|---|---|
| 一覧（.xlsx）の読み取り（よみがな・結合セル・全角括弧の扱い） | 0.5 |
| 市区町村の対応表を国土地理院のものへ差し替え | 0.25 |
| 施設コードの振り直しと写真の保存先の移動 | 0.25 |

**表の読み取りに手間がかかった理由:** よみがなが `<rPh>` として
セルの中に埋め込まれており、単純に読むと共有文字列の番号がずれて
別のセルの値になる。エリア見出しの空セルも数値として読めてしまい、
施設番号を誤る。専用の読み取りを書いた（`tools/lib/xlsx.mjs`）。

**対応表の差し替えが必要だった理由:** 従来は都心9区分を手で書いていた。
193件には千葉県（浦安・船橋）と大田区が含まれ、知らないコードが来ると
住所が空欄になる。国土地理院の表（1,919件）をそのまま取り込んだ。

**コードの振り直し:** お手元の一覧と画面を番号で対応させるご要望により、
施設コードを一覧の番号に合わせた（69番 → `HTL-0069`）。
写真の保存先もコードを含むため、あわせて移した。

関連: `tools/import-sheet.mjs`, `tools/build-catalog-from-sheet.mjs`,
`tools/lib/xlsx.mjs`, `tools/lib/muni.mjs`, `docs/09-data-issues.md`

### P-2. 権限の穴の発見と修正 — 判断 / 0.5人日

**何が起きていたか。** P-1 で `grant update (display_name)` と書き、
「直せるのは表示名だけ」のつもりでいた。実際には何も絞れていなかった。

Supabase は public スキーマの新しい表へ、**既定ですべての権限を
authenticated へ渡している。** 表を作った時点で全列の update を持って
おり、狭い grant を足しても権限は増えるだけで減らない。

結果、ログインした会員が `PATCH /rest/v1/driver_profiles` で自分の
`trial_ends_at` を 2099年に、`status` を `active` にできた。
**会員は誰でも無期限に無料で使える状態だった。** 本番で再現を確認。

**実害は無い。** 会員が1人もおらず、新規登録も閉じていた。

**なぜ気づけなかったか。** RLS は「どの行か」しか絞らず、「どの列か」は
列ごとの GRANT で絞る。その GRANT は**足すだけでは効かず、先に剥がす
必要がある**。逆向きの間違いで、SQL を読んでも見つからない。

**直し方。** いったん全部剥がしてから、要るものだけ渡し直す
（`20260908000003`）。検査に「会員は自分の無料期間を延ばせない」
「自分を支払い済みにできない」を足した。

同じ間違いが他に無いかも調べた。**列ごとの grant を使っているのは
ここだけ。** 操作履歴（`audit_logs`）も `grant select, insert` と
書いてあるだけで update/delete が渡っているが、RLS にその2つの
ポリシーが無いため塞がっている（ポリシーの無い操作は拒否）。

関連: `supabase/migrations/20260908000003_lock_driver_columns.sql`

### P-3. お気に入り・閲覧履歴の引き継ぎ — 依頼 / 1.5人日

機種変更で失われないよう、サーバーへ預かる。

| 作業 | 人日 |
|---|---|
| 表・権限（`driver_favorites` / `driver_history`） | 0.5 |
| 送り口（後追いで写す・失敗しても操作は通す） | 0.4 |
| 突き合わせ（足し合わせ・上限で削る・消された施設を送らない） | 0.4 |
| 検査（別の入れ物で開いて確かめる） | 0.2 |

**端末の中が主、サーバーは控え。** 画面が読むのは端末の中のままで、
電波の届かない駐車場でも一覧が出る性質を落としていない。
サーバーへは後追いで写し、写せなければ次に開いたときへ回す。

**寄せ方は「消えるより重複するほうがまし」。** 足し合わせ、同じ施設は
新しいほうの時刻を採る。片方に無いものを「外された」と見なすと、
圏外の端末が持っていたぶんで相手側を消してしまう。増えたものは押して
外せるが、消えたものは戻せない。

**消された施設は送らない。** サーバーの表は施設への外部キーを持ち、
管理者が消した施設を送ると弾かれる。まとめて送っているため、1件の
ために全部が入らなくなる。端末に持っている施設だけに絞ってから送る。
取り込みが済んでいない（施設を1件も持っていない）ときは今回は送らず、
次に開いたときへ回す。

**登録していない方のぶんは外へ出ない。** 検査で確かめている。

検査: `tools/test-carry-over.mjs` — **11 / 0**（本番）。
別の入れ物（localStorage を共有しないブラウザ）で開いて確かめている。
同じ画面で読み直しても、端末に残っているものが出るだけで確かめたことに
ならないため。

**記録の置き場所が変わる。** これまで「どのドライバーがどの施設を
見たか」は端末の外へ出していなかった。引き継ぐ以上、預かることになる。
線は3つ引いてある。

- 管理画面からは読めない（管理者向けの参照ポリシーを作らない）
- 会員は自分の行しか読めない
- 退会すれば消える

ただし service_role の鍵は RLS を迂回するため、運用者は技術的には
読める。**伏せずに発注元へお伝えした。**

ご指示（2026-09-09）:
起動したらログインの窓を出す／メールとパスワードを記憶し、次は押すだけで

**入口をひとつにした。** ログインしていなければ、どの道筋から開いても
入口が出る。会員制の製品として筋が通る形になった。

  **代わりに、登録していない方は何も見られなくなった。** これまでは
  登録せずとも193件を読めた。ご指示による切り替えであり、
  **新規登録が閉じたままだと、誰も入れない**ことになる。

**パスワードを端末に残すことについて。** ご指示のとおり実装したが、
伏せずに申し上げる。ブラウザには鍵を掛けてしまっておく場所が無く、
そのまま残ることになる。**同じパスワードを他所でもお使いの場合、
この端末を触れる人にそちらまで知られる。** そのため
  * 既定では控えない設定にはせず、印を付けた方だけとし（既定は入）、
  * 画面にも「共用の端末では入れないでください」と出し、
  * 印を外して一度入れば消える、
という形にした。メールアドレスだけは印が無くても控える（打ち直しの
手数が多く、知られて困る度合いが低い）。

**登録の確認欄。** 打ち間違えたまま登録すると、本人にも二度と入れない。
いまはメールの送信口が無く、再設定でも救えないため、確認は必須にした。

### P-6. 顔写真を変えても画面が変わらなかった — 不具合 / 0.2人日

**何が起きていたか。** 写真を選んでも何も起きなかった。

ブラウザは「窓へ戻る（focus）」を先に出し、「選ばれた（change）」を
後から出す。閉じられたことを知る手立てが無いため focus を合図にして
いたが、**500ms しか待たずに入力欄ごと片付けていた。** 選んだ中身が
届く前に消えるため、何も起きない。

**なぜ検査を素通りしたか。** 検査は setFiles で change をすぐ起こして
おり、本物の枠で起きる「focus が先、change が後」の順を作れていな
かった。加えて、名簿と置き場所だけを見て**画面を見ていなかった。**

**直し方。** 待つ時間を 2500ms へ広げ、そのとき入力欄に入っているものを
見て決める（change を待たずに済むので、遅れても取りこぼさない）。
cancel の合図にも対応した。display:none をやめ、画面の外へ置く
（一部のブラウザは display:none の入力欄への click() を無視する）。

あわせて「閉じただけ」と「読めなかった」を分け、後者は伝えるようにした。
どちらも無反応にすると、壊れているのか自分が閉じたのか判じられない。

**検査に足したもの。** 窓へ戻る合図を先に出し、少し置いてから選ぶ
（本物の順に近づける）。そのうえで**画面に出ているか**を見る

### P-15. 1つのアカウントは1台まで — 依頼 / 0.7人日

設計案で「決めておくべきこと」に挙げていた「1つのアカウントで同時に
使える端末数」が、1台に決まった（ご指示 2026-09-10）。

**後勝ちにした。** 先に入っている端末を優先して2台目を断ると、
機種変更・紛失・故障のたびに入れなくなり、こちらへ連絡して外して
もらうまで使えない。走行前の車内で起こると、その日は仕事にならない。
新しく入った端末を通し、前の端末が出ていく。

**仕組み**
- 端末ごとにでたらめな符号を一度だけ作って残す。**端末を特定できる値
  （広告IDなど）は使わない。** ログアウトしても消さない（同じ端末で
  入り直したときに自分を締め出すことになる）。
- ログインのたびに名簿へ控え、Supabase 側の鍵も落とす（scope: 'others'）。
  鍵だけでは前の端末の手元の鍵が切れるまで最大1時間効かないため、
  控えとの突き合わせで即座に効かせる。
- 控えが空のときは通す。この仕組みより前から入っている方を、いきなり
  締め出さない。

**途中で見つけた不具合を2つ直した。**

1. **入ったばかりの端末が自分を締め出していた。** ログインすると、控えを
   書き終える前に画面側が読みに来る（onAuthStateChange → loadAccount）。
   そのとき控えはまだ前の端末のままなので、食い違いと判定していた。
   書き終えるまでのあいだ、突き合わせを止めるようにした。
2. **出された理由が伝わらなかった。** 一瞬で消える帯に出していたため、
   戻ってきた画面を見たときには消えていた。入口へ出したままにし、
   次に入るまで残す。

**引き継ぎとは両立する。** 機種変更でお気に入りと履歴が引き継がれる
仕組み（P-3）はそのまま。止めているのは**同時に2台で使うこと**であって、
乗り換えではない。

**本番**: test-one-device 9 / 0・test-login 21 / 0・test-header 71 / 0。

`app/src/lib/device.ts`, `app/src/lib/account.ts`,
`app/src/components/auth-gate.tsx`, `tools/test-one-device.mjs`

### P-14. 料金の変更と、管理画面の骨組みの組み替え — 依頼 / 1.0人日

**料金**（0.1人日）: 月額 800円 / 年額 8,000円 → **月額 4,000円 / 年額

  広い画面でしか出せなかった。

### P-11. 端末側の鍵の更新と、会員一覧の詰め — 判断 / 0.4人日

**端末側で、久しぶりに開くとログインが切れる。**
ログインの鍵には期限があり、切れる前に取り替え続ける必要がある。
ブラウザは自前で回すが、端末側（Expo Go・APK）はアプリが裏へ回ると
止まる。止まったまま期限が切れると、次に開いたときに入口へ戻される。

  起動時にログインを求める作りにしたことで、これは「久しぶりに
  開いたら毎回打ち直し」という形で出る。表に出ているあいだだけ
  鍵を取り替える形にした（AppState）。裏では止める。見られていない
  アプリのために取り替え続けても電池を使うだけ。

**会員一覧を「手を打つ順」に並べ替えた。**
会員番号順では、期限切れの方が下に埋もれる。番号は振込の突き合わせに
使うもので、眺める順ではない。

  期限切れ → 無料期間（期限の近い順）→ ご利用中 → 停止中

あわせて、

- 期限が過ぎた方に**「期限切れ」**と出す（以前は切れても「無料期間」）
- 期限の欄へ「あと◯日」「◯日超過」を添える
- 内訳（期限切れ◯名・無料期間◯名…）を見出しの横に出す
- メールアドレスから**そのまま連絡できる**ようにする

  入金の催促も、停止のお知らせも、ここから始まる。

関連: `app/src/lib/supabase.ts`, `admin/src/app/(admin)/members/page.tsx`
