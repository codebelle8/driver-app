## 作り方の決まり

* **使えるかどうかを決めるのは、いまと同じ `paid_until` 1つ。** 画面の絞り込み（`plan-gate`）、圏外の控え、
  上位の方の無料、試験提供が、すべてここを通っている。別の決め手を足すと、電波の無い場所でだけ締め出される、が起きる
* **`paid_until` を書くのはサーバーだけ。** Stripe からの知らせ（署名を確かめる）を受けて書く。アプリから「払った」とは書かせない
* **同じ知らせが2回届いても、二重に延ばさない**（知らせの番号を控え、済んだものは飛ばす）
* **カード番号はこちらを通さない。** 入力は Stripe の画面で行う（割賦販売法の「持たない」。本人確認の 3Dセキュアも Stripe が行う）
* 銀行振込の「入金を確認した」は残し、並べて使う

### データベースの形（2026-11-26）

`supabase/migrations/20261126000001_payments.sql`。検査は `db/tests/0017_payments_tests.sql`。

| もの | 中身 | 会員から |
|---|---|---|
| `payments` | お支払いの記録（1回1行）。金額・消費税・期間・領収書の番号・返金。**退会しても残す** | 自分の分を読める（Stripe の番号は除く） |
| `member_billing` | 自動更新の状態（次の更新日・解約の予定・決済できなくなった時刻）、Stripe の顧客の番号 | 自分の状態を読める（Stripe の番号は除く） |
| `stripe_events` | 届いた知らせの控え（番号・種類・時刻だけ。中身は持たない） | 読めない |
| `paid_period_start()` | 有料の期間の始まり（いま・お支払い済みの期間・無料期間・**上位の方の無料の月**のうち遅いほう）。2026-11-26 `20261126000002_paid_start.sql` | 呼べない（サーバーだけ） |
| `record_payment()` | 記録して `paid_until` を延ばす。始まりは `paid_period_start()`。同じ番号は2回目から何もしない | 呼べない（サーバーだけ） |
| `sync_member_billing()` | 自動更新の状態を合わせる。古い知らせは捨てる。決済できなければ7日間延ばす | 呼べない（サーバーだけ） |

* **期間：** Stripe の自動更新は請求書の期間をそのまま使う（決済が遅れても Stripe は更新日をずらさない）。
  PayPay・銀行振込は、無料期間・お支払いの期間・上位の方の無料の月のうち遅いほうの終わりから数える
  （`paid_period_start()`。カードの最初の決済日も、受け口の段でこれに合わせる）。月は日本時間の暦で数える。
  上位の無料の月を入れたのは、無料期間を過ぎた方が無料の月の途中で申し込んだとき、無料の日数ぶん払わせない
  ため（第6条5項）。アプリの申込みの最後の画面（`app/src/lib/checkout.ts`）も同じ決め方で日付を出す
* **7日間の猶予（第9条）：** 最初に決済できなくなった時刻から7日後まで、アプリが見ている終わり（お支払い済みなら
  `paid_until`、無料期間なら `trial_ends_at`）を延ばす。やり直しでまた失敗しても起点は動かない
* **管理画面の「入金を確認した」は、まだいまのまま**（`actions/members.ts` の `nextPaidUntil`）。管理画面の段（7）で
  `record_payment()` に乗せ替え、銀行振込の記録と領収書もそこから出す
* 上位の方の無料で `paid_until` が1か月延びた自動更新の方は、Stripe の次の決済も1か月後ろへずらす（受け口の段で作る）。
  ずらし忘れても、`record_payment()` は期限を縮めない

### 申込みの最後の画面（2026-11-26）

`app/src/app/checkout.tsx`（`/checkout?plan=monthly&method=card`）。中身は `app/src/lib/checkout.ts`。
検査は `tools/test-checkout.mjs`（計算）と `tools/test-checkout-screen.mjs`（画面）。

* **並べるもの**（特定商取引法 第12条の6）：料金プラン・支払方法・ご利用の期間・自動更新／金額（税込）・
  お支払いの時期・ほかにかかる費用／ご利用の開始／解約（自動更新の止め方）と返金。申込みの期間は設けていないので出さない
* **日付はデータベースと同じ決め方**（始まりは `paid_period_start()`、終わりは日本時間の暦で月を足す）。画面だけ、
  データベースだけを直さない
* **有料での提供を始めたかは、サイト設定の `trial_open` を直接読む**（`app/src/lib/paid-open.ts`）。無料の理由の
  'trial' では見分けられない（上位の方は試験提供の期間中でも「上位」と返る）。読めないときは「まだ」として、
  これまでの画面（ご希望を控える）のまま
* 試験提供の期間中も、URL を開けば見本として見られる（釦は押せない）。弁護士にお見せする文案は、この画面から作る
* **まだつないでいないもの**
  * 釦の先：カード・PayPay は 3 で Stripe の支払い画面を開く（`STRIPE_CONNECTED`）。銀行振込は、この画面を通った
    申込みと、試験提供の期間中の「ご希望」を見分ける欄（例：`driver_profiles.plan_method`）を足してから
    （`TRANSFER_CONNECTED`）。それまで、有料での提供を始めたあとは、お支払いの画面に振込先を出さない
  * Stripe の画面の側にも要点を添える（`custom_text`。カード・PayPay は、Stripe の画面で申込みが完了するため）
  * カードの更新日は「毎月◯日（その日が無い月は月末）」と出す。Stripe は UTC で月を数えるので、月末の朝9時前に
    始まった方だけ、日本時間で1日ずれることがある（利用規約 第8条3項「前後することがあります」の範囲）。3 で
    `billing_cycle_anchor` の決め方を確かめる

### 規約と組み合わせるところ

* 無料期間の途中で申し込んだ方は、残りの日数のあとから有料の期間を始める（第5条2項）
* 上位20名に入った有料の方は、1か月延ばす。自動更新の方は、次の引き落としを1か月後ろへずらす
* 12か月払いの途中解約は、第11条の計算（残りの月数 − 2）× 500円 で返金する。管理画面で金額を出す
* 有料を始める時点で無料期間を過ぎている方は、そこから1か月無料（第4条7項）

## 気をつけること

* **PayPay（Stripe）は都度払いだけ。** Stripe の資料で継続課金は対応外。自動更新の支払い画面には出せない。
  1か月分・12か月分をその都度買っていただき、期限が来たらあらためて手続きいただく（第7条10項）
* PayPay は Stripe の管理画面で別に有効にする必要がある（審査があるか、個人事業主で使えるかは、お申し込みの際に確かめる）
* **領収書（適格請求書）** には、登録番号と、税率ごとの消費税額（10%）が要る。Stripe の料金は「税込 10%」で作る
* **銀行振込の方の領収書は Stripe から出ない。** こちらの仕組みから出す必要がある（4 か 7 で扱う）
* 将来アプリストアに出す場合は、そのときにストアの課金の決まりを確かめ直す
