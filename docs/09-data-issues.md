## 取り込みの方針

### 施設名はいただいた表記のまま

当方で正式名称へ直さない。一覧と画面が1対1で対応していないと、
クライアント様が確認される際に照合できなくなるため。

正式名称や略称は**別名**に入れてあり、検索はどちらでも届く。
たとえば「ミマル東京銀座イースト」は `MIMARU東京 銀座EAST` でも引ける。

### 進入路の注記もいただいた文面のまま

当方で言い換えると、原文にない意味が混ざる。

たとえば「地下駐車場B2Fから27F」を「27階へお上がりください」と書き換えると、
27階が受付なのか通路なのかを当方が決めてしまうことになる。
B2F / 1F の表記は乗務員の方には通じるため、そのまま出す。

### 住所は座標から引いている

いただいた一覧に住所は無い。国土地理院の逆ジオコーディングを使い、
座標から**町丁目まで**を割り出している（`tools/fill-addresses.mjs`）。

鍵もアカウントも不要で、国が整備した住所データが返るため、
Google Maps の API キーを待たずに進められた。

### 「車寄せ」有無の扱い

一覧の「有」「無」を、進入口の種別に対応させている。

| 一覧 | 進入口の種別 | 画面の表示 |
| --- | --- | --- |
| 有 | dropoff | 車寄せ |
| 無 | entrance | エントランス |

### 座標が2つある施設

一覧の「エントランス・車寄せ進入路」欄は、座標2つ分の幅にまたがっている。
2つ目の座標が入っているのは **帝国ホテル東京** と **ザ・ペニンシュラ東京** の2件のみ。

この2件は進入口を2つ登録し、2つ目を「進入路 2点目」としている。

## クライアント様にご確認いただきたいこと

### 1. 番地

座標から引けるのは町丁目まで。番地は分からない。

例: 帝国ホテル東京 → 千代田区内幸町一丁目（番地は未確認）

### 2. 2つ目の座標の意味

帝国ホテル東京・ザ・ペニンシュラ東京の2件だけに2つ目の座標がある。

これが「進入路の入口（道路から入る地点）」なのか、
「別の車寄せ」なのかで、画面での見せ方が変わる。

参考: 帝国ホテル東京の2つ目の座標は、レム日比谷のエントランスから
21m の位置にある。日比谷通り側から入る地点と考えると辻褄が合う。

### 3. 35m しか離れていない2件

- ACホテル・バイ・マリオット 東京
- コートヤード・マリオット 銀座東武ホテル

いずれも中央区銀座六丁目で、隣接する別の建物と思われるが、
どちらも Marriott 系のため、念のため確認したい。

### 4. 「東京駅・銀座」が2つに分かれている

一覧では「東京駅・銀座」の見出しが2回出てくる（19件 + 10件）。
後半10件は1件を除いて車寄せが「無」で、調査時期が違うようにも見える。

この分かれ方に意味があるか（別のグループとして扱うべきか）を伺いたい。
現在は35件すべてを1つのまとまりとして登録している。
